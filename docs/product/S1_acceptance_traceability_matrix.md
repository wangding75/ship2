## 5. 标准证据包字段契约（Section 7 Evidence Record Contract）

依据《S1任务与验收细则》第 7 节，自 `S1-T04` / `S1-T16` / `S1-T18`～`S1-T22` 起的每个运行与验收证据项，除满足 `specs/review_record.schema.json` 的 15 个顶层必填字段外，运行证据清单必须完整包含以下 19 个关联追踪字段（无适用项时显式填 `NOT_APPLICABLE_*` 或 `null` 并注明原因，严禁静默省略）：

| 序号 | 字段名 | 类型 | 必填说明与取值规范 |
| --- | --- | --- | --- |
| 1 | `task_id` | `string` | 任务标识，如 `"S1-T01"` ～ `"S1-T22"` |
| 2 | `requirement_ids` | `array<string>` | 关联的需求编号列表，如 `["REQ-S1-011", "REQ-S1-012"]`（范围限于 `"REQ-S1-001"` ～ `"REQ-S1-026"`）及对应 `S1-ACxx` |
| 3 | `artifact_id` | `string` | 候选产物版本唯一标识 |
| 4 | `artifact_sha256` | `string` (64 hex) | 受检产物包或核心文件的 SHA256 哈希 |
| 5 | `source_commit` | `string` | Git 提交 SHA；无 Git 仓库阶段固定填 `"NOT_APPLICABLE_NO_GIT"` |
| 6 | `build_sha256` | `string \| null` | `S1-T17` Windows / Android 构建包 SHA256（纯文档/源码阶段填 `null`） |
| 7 | `toolchain_lock_hash` | `string \| null` | `toolchain_lock.json` 的 SHA256（`S1-T03` 锁定后必填） |
| 8 | `scenario_seed` | `integer \| string \| null` | 场景与测试确定性随机种子（世界/航行/测试任务必填） |
| 9 | `device_profile` | `object \| null` | 实测设备型号、SoC、RAM、OS 版本、ADB 序列号或 PC 硬件信息 |
| 10 | `render_profile` | `object \| null` | 渲染管线（URP）、画质档位、内部渲染分辨率（如 `1280x720`）、帧率上限设置 |
| 11 | `run_id` | `string` | 产生该证据的 Multica Run UUID |
| 12 | `started_at` | `string` (ISO 8601 UTC) | 运行开始 UTC 时间戳 |
| 13 | `duration` | `number` (`seconds`) | 实际运行持续秒数（如性能测试预热 `300 s` + 正式测量 `1800 s`） |
| 14 | `raw_files` | `array<string>` | 原始日志、CSV/JSONL 时间序列、截图、录屏及各自 SHA256 列表 |
| 15 | `producer_agent_id` | `string` (UUID) | 制作者 Agent UUID |
| 16 | `reviewer_agent_id` | `string` (UUID) | 独立验收者 Agent UUID（必须满足 `producer_agent_id != reviewer_agent_id`） |
| 17 | `verdict` | `enum` | `"PASS"` / `"FAIL"` / `"BLOCKED"` / `"NOT_RUN"` |
| 18 | `failure_reason` | `string \| null` | 当 `verdict == "FAIL"` 时的精确失败原因与最小复现步骤 |
| 19 | `missing_evidence` | `array<string>` | 当 `verdict == "BLOCKED"` 时缺失的外部输入、设备或前置证据及恢复条件 |
