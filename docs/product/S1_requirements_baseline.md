## 2. 第一阶段（S1）目标与范围边界（In-Scope vs. Out-of-Scope）

### 2.1 第一阶段核心交付目标（In-Scope）

第一阶段（S1）唯一交付目标是构建一个**符合用户图 4（`references/style/figure04_ocean.png` 右侧“丰富水面示意”）方向的、可安装运行的真实 3D 海岛世界与可操作舰船航行系统**。当本文件与任何历史非冻结文档冲突时，以本需求基线及同源冻结规格（`S1_tasks.json`、`S1_acceptance.json`、`task_acceptance.json`、`S1任务与验收细则.txt` 及已登记的 `figure04_ocean.png`）为准。

S1 纳入范围的功能与验收域包括且仅包括：
1. **真实 3D 海岛世界**：`2048 m × 2048 m` 世界米起测范围；3 种基础岛型模块、12 个岛屿场景实例、1 个港口地标（Port Landmark）及位于可航水域内的合法停泊锚点（Port Anchor Point）；场景布局与障碍支持由固定 `scenario_seed` 确定性重建。
2. **符合图 4 右侧“丰富水面示意”方向的海水、浅滩、岸线与尾迹表现**：真实 3D 水面网格，呈现浅滩暖沙→青绿浅水→中水蓝绿→深蓝深水的多层过渡、水下礁石暗影、连续清晰的白色岸线泡沫环带及温和波浪动态；舰船航行时按世界轨迹生成弯曲渐隐的白色泡沫尾迹，停船后自然衰减，转弯圆滑不僵直、不穿岸；近/中/远机位及低画质档位保留关键视觉层次；严禁退化为图 4 左侧“平坦水面示意”的单调水面与生硬折线岸线。
3. **三种真实 3D 舰船资产与主船控制**：3 种真实 3D 网格船型，具备合理水线、枢轴（Pivot）、碰撞代理（Collision/Navigation Proxy）、尾迹挂点及 `LOD0 / LOD1 / LOD2`；支持 360 度连续转向无破面；世界中 **1 艘主船（Player Controllable Ship）** 可由玩家点选操控。
4. **完整单船航行闭环操作**：选船 → 点击可航水域目的地 → 自动规划绕岛路径并平滑航行 → 抵达目标容差圈；支持航行中主动**停止**、航行中动态**改目标**、点击非法区域时给出**不可达/越界反馈**、点击**返航**自动驶回港口合法停泊锚点。
5. **俯视相机与最小航行 HUD**：符合图 4 右侧倾斜俯视构图方向的俯视起测机位（默认起测俯角目标 `55.0° ± 2.0°` 源自 Owner 方向与冻结 `S1-AC02` 规格，非 PNG 图像测量）；支持地图平面拖动、连续缩放、选船跟随、一键复位与世界边界限制；PC 鼠标与 Android 真机触控交互语义等价；HUD 实时显示船名/船型、目标、剩余距离、当前速度、航行状态，并提供停止、返航、相机复位控件；点击任何 UI 控件绝不穿透为航行命令；适配 `16:9`、`20:9`、`4:3` 画幅安全区。
6. **导航正确性（100 条合法路线 + 独立不可达负例）**：100 条独立冻结的合法路线（覆盖短途、长途、贴岸、窄通道、岛后绕行、急转弯、港口往返）100% 到达；不可达负例单独检测并 100% 正确拒绝；整个船体导航代理扫掠区域不穿岛、不瞬移、不越界。
7. **20 次场景重入恢复**：连续 20 次场景重入无重复船、无孤儿对象、无重复事件订阅；最小主船位置与镜头状态按本规格冻结规则恢复。
8. **30 船同屏运动性能与热稳定**：按当前已签核冻结规格，在登记的 6GB RAM Android 真机、`720p` 内部渲染分辨率下，同屏运行 **1 艘可控主船 + 29 艘实际运动且带尾迹的可见压力船（共 30 艘）**；预热 5 分钟后连续测量 30 分钟，满足 `p95 帧时 ≤ 33.3 ms`、观测总 PSS 内存峰值 `≤ 1.2 GiB` 且无持续内存增长、无崩溃、无运行时 Error。（注：Owner 已在 `project_inputs_20261106_registered.json` 确认 Windows-only `1920×1080` / `30fps` / `p95≤33.3ms` / 低-中档方向，相关规格修订正在 `SHIP-9` 独立审核中；在经 G14 正式重签前，本基线保留原 Android 冻结条款与冲突说明，不降低 `33.3 ms`、不删除 PSS/内存检查、不直接将 PSS 替换为 Windows 指标。）
9. **双端可重复构建、图 4 资产入库与测试有效性门禁**：`S1-T03`（负责人 `A14`）初始化 Git 仓库后将 `figure04_ocean.png` 提交至 `references/style/figure04_ocean.png` 纳入版本管理；干净 commit 生成候选包，无编译错误、丢失引用或粉色材质；测试脚本至少能捕获 3 类受控注入故障；全部 required 任务具备作者分离（G01/G02）与哈希绑定的独立验收证据。

### 2.2 第一阶段明确排除项（Out-of-Scope / 严禁引入）

为确保第一阶段范围收敛与验收边界清晰，以下内容**严禁在 S1 中设计、实现或作为伪按钮展示**：
1. **不引入采集、资源结算或商业化经济**：返航仅抵达港口水域合法停泊锚点（`Arrived` 状态），不触发货物卸载、资源增减、金币/钻石账本、商店价格或建造升级结算（`A16` / `A17` 在 S1 保持未启动）。
2. **不引入海战、技能或伤害系统**：S1 无火炮射击、碰撞扣血、沉船销毁、敌我阵营仇恨或战斗结算。
3. **不引入多船编队控制或多人网络同步**：30 船性能场景中的其余 29 艘船仅为实际更新运动、尾迹与可见渲染的本地压力船，**不代表 30 个真实网络玩家，也不代表三船/多船编队协同操控**；玩家同一时刻仅操作唯一主船（`ActivePlayerShipCount == 1`）。
4. **不引入港口内城、船坞建造、英雄或赛季 UI**：HUD 仅保留最小航行信息与控制按钮，严禁在界面上放置未实现的“基地/英雄/抽卡/联盟/背包”假按钮（S1 终验要求核心功能假按钮数为 `0`）。
5. **不指定未验证的平台原生能力**：不假定 Multica 已内置自定义动态 Workflow 处理器或原生导入 `S1_tasks.json` / `agents_registry.json`；自动 Gate 程序在 `S1-T03` 完成前处于 `implementation_required` 状态，不在 `S1-T01` 宣称自动 Gate 已运行。
6. **不臆造图 4 中不存在的画面细节或伪造图像测量来源**：`references/style/figure04_ocean.png` 为水体/岸线/岛屿/单船尾迹的双面板对比图，无相机元数据、无角度标注、无几何比例尺；图中不包含 HUD 界面、不包含港口地标建筑、亦未并列展示全部 3 种船型网格；这些图中未出现的细节在图 4 视觉引用中保持 `null`/待补，严格按文字规格由 `S1-T05`/`T06`/`T07`/`T13` 细化，且绝不将 Owner/规格起测角度（`55.0° ± 2.0°`）或工程建议初值（如 `85 m` 机位高度、水道 `4～8` 倍船宽）伪称为“从图 4 测量读出”。
